# 10 – UI: the look and the CSS

The store looks like a magazine. Pages are made of full-width rounded **chapters**, each in its own
colour, with big editorial headlines and cards that scroll sideways. Surfaces are **neumorphic**: a
card is the colour of the page it sits on, raised by a soft glow above and a shade below, or pressed
into it. The light always comes from straight above. There are no outlines.

Dictated 2026-11-08 (store profile, Decisions). Colours: `src/themes/palette.css`. Utilities:
`src/app.css`.

## Chapters

A chapter switches a section to another palette. Everything inside it (text, buttons, cards, inputs,
template components too) takes the new colours, because every utility reads the palette it sits in.

| Utility           | Colour                       | Use it for                                                                                   |
| ----------------- | ---------------------------- | -------------------------------------------------------------------------------------------- |
| `chapter-paper`   | warm cream (the page itself) | the default; most of a page                                                                  |
| `chapter-ink`     | deep brand teal              | the big sections: schools on the home page, a school's header, the footer, the admin sidebar |
| `chapter-wine`    | brand burgundy               | a second strong section (categories on the home page); "taking orders" when off              |
| `chapter-saffron` | warm amber                   | a closing call to action                                                                     |

Add `chapter` for the rounded corners and the generous padding:

```css
section.schools {
	@apply flex flex-col gap-4 chapter chapter-ink;
}
```

`palette-ink` (and the others) set only the colours, without background or padding, for a surface
that should take a chapter's palette.

## Surfaces

| Utility                                                                                   | What it is                                                                                      |
| ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `raised`                                                                                  | a card raised out of the page: glow above, shade below                                          |
| `sunken`                                                                                  | pressed into the page: inputs, wells, tracks, the selected tab                                  |
| `floating`                                                                                | over the page: dialogs, drawers, menus, toasts (the lightest layer); shade below, no glow above |
| `raised-primary`, `raised-secondary`, `raised-danger`, `raised-success`, `raised-warning` | a raised colour (buttons, pills)                                                                |
| `press`                                                                                   | sinks 1px into the page while pressed                                                           |

Shadows `shadow-s`, `shadow-m`, `shadow-l` and `shadow-inset` are the same light in Tailwind's shadow
scale. Checkboxes and radios take `shadow-inset` only, so their tick still shows. Selects take
`control`: a surface's gradient would cover the forms plugin's arrow, so `control` draws the arrow
on top of it (`raised` and `sunken` keep their gradient in `--surface` for this).

## Type

One display font, Manrope (self-hosted, Latin about 25 KB), for headlines only; reading text stays in
the phone's own font. All `h1` to `h3` use it.

| Utility         | Use it for                                                                                |
| --------------- | ----------------------------------------------------------------------------------------- |
| `type-display`  | the one big headline of a page or chapter                                                 |
| `type-headline` | a section title, or the page title on a working page (admin, forms)                       |
| `type-title`    | a card's title                                                                            |
| `type-kicker`   | the small spaced capitals above a headline                                                |
| `text-accent`   | the coloured second line of a headline (`<span class="accent">`, styled in the component) |

`src/lib/store/PageHead.svelte` puts these together for the top of a page: back link, kicker,
headline (with an optional accent line), lead, and optional buttons or pills. `tone="ink"` (or
`wine`, `saffron`) puts it in a chapter; `size="headline"` is for working pages.

## Rails

`rail` makes a list of cards scroll sideways with the thumb and snap to each card (most of a phone's
width per card; 18rem from `sm`).

## Photo slots

There are no professional photos yet. Every photo spot is a `Media` slot (`src/lib/ui/Media.svelte`):
with a `src` it shows a lazy image of a fixed shape; without one it shows a soft, pressed-in
placeholder in the chapter's colours with a faint icon. Customers see no "coming soon" text.

Each slot has a name, set as `data-media` on the element, so finding where a photo goes is a search
(`grep -rn 'slot="home-hero"' src`).

| Slot              | Where                                 | Shape | Photo source                            |
| ----------------- | ------------------------------------- | ----- | --------------------------------------- |
| `home-books`      | home masthead, first tile             | 4:3   | to add (a static image)                 |
| `home-uniform`    | home masthead, second tile            | 4:3   | to add                                  |
| `home-stationery` | home masthead, third tile             | 4:3   | to add                                  |
| `home-how`        | home, beside "How it works"           | 4:3   | to add                                  |
| `shop-front`      | home, closing chapter                 | 4:3   | to add (a photo of the shop)            |
| `school-cover`    | home schools rail, `/schools`         | 4:3   | to add (needs a photo field on schools) |
| `signin`          | `/signin`, desktop only               | 4:3   | to add                                  |
| `product-cover`   | product cards                         | 3:4   | the product photo (admin)               |
| `product-photo`   | product page                          | 3:4   | the product photo (admin)               |
| `product-thumb`   | set picker, cart, search, admin lists | 3:4   | the product photo (admin)               |

Product photos already flow in from the admin. The other slots take a static image (for example under
`static/`) or, for schools, a new photo field later.

## The CSS rule

No Tailwind utilities in markup: only short class names that say what the thing is. Each component's
`<style lang="postcss">` has one root selector written as **element + class**, with everything else
nested inside it, and short `@apply` lines for the declarations:

```svelte
<section class="schools">
	<h2 class="title">{text.schoolsTitle}</h2>
	<ul class="cards">…</ul>
	<a class="more" href="/schools">{text.allSchools}</a>
</section>

<style lang="postcss">
	@reference 'src/app.css';

	section.schools {
		@apply flex flex-col gap-4 chapter chapter-ink;

		h2.title {
			@apply type-headline;
		}
		ul.cards {
			@apply rail;
		}
		a.more {
			@apply inline-flex min-h-11 items-center font-bold text-accent;

			&:hover {
				@apply underline;
			}
		}
	}
</style>
```

- Elements Bits UI renders itself (dialog content, select items, switch track) are styled in a
  `:global { div.ui-modal { … } }` block, since they are outside the component's scope.
- A child component is reached with `:global(...)` only where there is no other way.
- **Never name a class after a utility** (`title`, `rail`, `panel`, `grid`, `block`, `raised`):
  Tailwind sees the name in the markup and applies the utility everywhere it appears.
- Template files (`src/lib/ui`, `src/lib/primitives`, `src/lib/auth`, `src/routes/account`) keep the
  template's formatting (spaces, double quotes in `src/lib/ui`).
